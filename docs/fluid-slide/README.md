## Evidence

- **PASS:** 32 focused controller/PWA tests, JavaScript syntax and diff checks. The first PWA run correctly rejected the bumped cache version until its expected version was updated.
- **PASS:** [40 DPR2 A/B samples](token-batch-ab-results.json), Chromium 157.0.8103.78, isolated signed-out local fixtures at 835/1280px. [Harness](token-batch-ab.js) pins both controller variants. Calendar style recalculations fall from 60–61 to 54 and layouts from 13 to 11. Warm Calendar update callbacks measure about 5.0–5.4ms before and 4.3–5.1ms after. All 20 candidate samples have at most 16.8ms measured RAF gaps after readiness. Baseline mostly had the same steady frame rate, so this demonstrates less preparation work, not a universal FPS improvement.
- **PASS:** [Eight trusted moving-control cases](moving-input-results.json), quick and held task checkboxes/Calendar slots at 835/1280px. The harness waits for actual animation time to advance before sampling the painted hitbox, then checks the precise task or scheduled date/time. An initial background-context attempt timed out during cleanup; bringing the isolated page to the foreground resolved it. A first cold sample at time zero was not accepted as moving-input evidence and the strengthened harness was rerun.
- **PASS:** [Five fallback cases](fallback-results.json): touch 320/390px navigation, Add Task and Tasks sheet; reduced motion; unavailable and throwing capture APIs. Three targeted interruption cases also pass: rapid reversals, keyboard focus/search and resize, with no residual names, attributes or animations.
- **PASS:** [Normal DPR2 playback](fluid-slide-835.webm) and [decoded filmstrip](filmstrip-835.png), plus the actual open in-app browser (Chromium 157, DPR2) refreshed to the final controller. Calendar→Dashboard→Calendar completed, with one outline and zero residual transition names/attributes. The user's Week view and scroll positions were restored without editing records. Its screenshot remains in private temporary storage.

The actual in-app browser was also measured using a temporary loopback-only DOM probe, removed before the final checkpoint. Cold and warm timings varied, including occasional startup gaps; no claim that every hardware/browser hitch is eliminated. Extra transient layer hints and non-inheriting clip variables were investigated and rejected because neither showed a repeatable improvement. No additional wait, permanent layer hints, broader grouping or bounce removal was introduced. The local ffmpeg installation could not decode the video because its x265 library is missing; Chromium decoded the recording successfully for visual review.

**NOT RUN:** signed-in/backend parity, installed PWA, physical Safari/iPhone/iPad and native WKWebView. These are separate runtimes and outside this local presentation change. No main merge, public deployment, backend migration or native bundle synchronization.
