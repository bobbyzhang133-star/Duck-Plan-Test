# Work start and end times — November 26, 2026

Work time now uses Start date, Start time, End time and End date, with a Clear work time action. The duration dropdown is removed. Changing the start moves the end to preserve the last valid length; editing the end chooses a new length. Collapsed summaries show both endpoints, including the end date for overnight work.

The existing saved format remains `scheduledStart` plus `durationMinutes`; the new endpoint validator derives those fields before saving. No API/schema change or task migration is required. Existing custom lengths and explicit legacy end values populate the corresponding endpoints. Overnight/full-day civil ranges preserve the existing calendar arithmetic, including DST boundaries. Work dates/times remain separate from deadlines; reminders, alerts, notes and saved IDs retain their existing behavior. The previous 5-minute to24-hour range limit is enforced with a field-specific error, rather than silently treating an earlier end time as tomorrow. Clearing work removes the schedule while preserving the task and its saved preferred length. Templates retain their duration-only definition; Schedule opens the task editor with corresponding start/end fields.
