# Calendar time-label and current-time cutoff fix — November 16, 2026

The user clarified that the reported cutoff concerns **time labels and the red current-time line**, rather than shortening task/block titles. Scope: the current local `DuckPlan-motion-preview` website, based on `d2cd297`. No task data, scheduled times, storage/API behavior or native app project changes are included.

## Fix

- Wider time gutter:72px on desktop/iPad and64px on phone, matching the existing short-landscape phone query. Labels retain their original font size and stay centred on hour lines; midnight is inset inside the initial edge.
- An inner label element separates text bounds from the full hour cell. The red line/dot is inset inside the day column, preserving its exact time coordinate and pointer-transparent behavior.
- A small `calendar-viewport.js` controller uses IntersectionObserver to hide only labels/indicators that are partially covered by sticky headers or scroll edges. Fully visible labels and the full current-time indicator reappear automatically. Header/root ResizeObserver and calendar child-list changes rebuild bounds; callbacks are generation-guarded and retired observers release their targets. There is no new per-scroll layout-reading loop. Unsupported observers retain the CSS-sized ordinary timeline.
- In short phone landscape, the toolbar/weekday selector already identifies the day. Its duplicated grid date row is collapsed so a usable part of the timetable and full time labels remain visible. Phone navigation, Tasks summary and seven-day selector remain available.
- Final cache70 includes the new module, with final version keys on index/CSS/app/controller. Work/deadline geometry, task/block materials, dialogs and existing navigation interactions are preserved.
