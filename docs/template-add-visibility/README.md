November 14, 2026, based on `75c6914`, branch `codex/template-add-visibility-20261114`. The investigation/common callback checkpoint is `cd346d0`.

The reported Calendar template button saves successfully, but its result is hidden. A new template copy has neither a deadline nor scheduled work. Calendar stays on Templates after saving, and its Tasks grouping excludes undated/unscheduled records. The full Tasks page contains the saved copies. Existing user copies were not removed or changed.

PASS reproduction: an isolated trusted 835px Add click saved exactly one independent copy, retained the source template and survived reload, while producing no visible Calendar task row. The user confirmed that successful copies belong in the Calendar task bar as unscheduled tasks. Calendar's Tasks tab now has a separate **Unscheduled** section for unfinished tasks without a deadline or scheduled work, including copies added before this fix. Adding a template reveals and focuses the saved row after durable success, switches to Tasks and opens the phone sheet when needed. Only the task column scrolls to the new row; the selected date, calendar viewport and original template remain intact. The row can open the existing editor or be dragged onto the calendar.

The computed `backlog` group is separate from date-specific due/scheduled/completed groups. No date or deadline is assigned, and undated work does not change daily completion percentages, Dashboard progress or mascot totals. The phone task summary includes the available unscheduled count. Scheduled or completed work leaves the unfinished backlog. Existing data is not rewritten or deduplicated.

The optional host `onTaskAdded(task)` notification runs after the unscheduled copy is durably saved and pending/render cleanup completes, only for the current owner/generation. Scheduled drops, failed saves, pending duplicate clicks and obsolete owners/destroyed views do not reveal a row or navigate another account.
