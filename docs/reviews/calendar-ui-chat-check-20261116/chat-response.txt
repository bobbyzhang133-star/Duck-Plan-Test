2. Exact-time deadlines are implemented correctly

This is one of the most important checks.

The current code generates a deadline diamond at the exact minute position in the 24-hour grid.

For example, an assignment with work scheduled from 3:00–4:00 PM and a deadline at 5:15 PM produces two calendar representations:

Friday's timetable

Illustrative layout

3:00 PM

Calculus homework

3:00–4:00 PM · Work

4:00 PM

5:15 PM

Deadline · Calculus homework

The source also handles three harder cases:

Multiple deadlines close together form a grouped control, with an expandable list.

If a deadline label conflicts visually with a work block, the layout reserves a separate annotation area.

A date-only deadline does not get an invented exact-minute marker.

This matches the settled requirement. The older design where all deadlines appeared above the grid has been superseded.

3. Remaining findings, ranked
P2 — Full Tasks-page Today filter uses only due dates

In landing/app.js:599, the separate Tasks page's Today filter still checks:

JavaScript
task.dueDate === nowKey() && !task.completed

That means an assignment scheduled for work today but due tomorrow is not included in that particular Today filter.

This does not violate the agreed Calendar task-panel behavior, which uses a separate grouping system. But it is a consistency issue for the overall product.

Recommendation: Later, decide whether Today on the Tasks page means due today, planned today, or both. I would lean toward both, with separate labels.

P2 — Dense deadline/work collisions reduce the work block's width

In landing/app.js:852–871, a work cluster sharing vertical space with a deadline annotation gets approximately 56% of the column width.

This is an intentional collision-handling strategy, and the implementation preserves both objects' interactions. It is not a confirmed bug.

However, a busy seven-column Week view could produce narrow work blocks with truncated titles.

Recommendation: During your local browser check, inspect a day containing overlapping work sessions and several nearby exact-time deadlines. If it feels cramped, refine the collision presentation rather than removing either item.

No longer an issue — “Due, not scheduled” heading

My preceding review flagged this heading as misleading.

The exact current source already fixes it. index.html:109 now uses “Due this day.”

That is the correct wording because the section can contain tasks due on the selected day even when work is scheduled for another day.

No additional change is needed.
