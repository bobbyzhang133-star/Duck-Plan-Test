3. Implementation instructions for Codex

Source baseline: bobbyzhang133-star/Duck-Plan-Test, reviewed commit ddac1c06300f4af0634f4266dee6b884b27a7928.

Step 1 — Create a shared daily count calculation

Use a pure function that takes tasks and a date and returns:

JavaScript
{
  workCount: 3,
  dueCount: 2
}

Count unfinished tasks as follows:

workCount: unique tasks whose Model.scheduledParts(task)?.date matches the header's date.

dueCount: unique tasks whose dueDate matches the header's date, whether dueTime exists or not.

Completed tasks contribute to neither count.

A task with both its work and due date on the same day contributes once to each category.

An overnight work session is counted on its scheduled start date, consistent with the current Calendar model.

Do not calculate these numbers using Model.groupForDate(), because that function assigns tasks to exclusive list groups. The two header counts must be independent.

Prefer reusing the existing task model's local date conventions rather than introducing UTC date conversion.

Step 2 — Update desktop and iPad day headers

Primary location: landing/app.js, renderTimeline(dates).

Extend .calendar-date-button to include a compact, icon-based count row beneath the date number.

Update the relevant styling in planner-motion.css and calendar-date-clarity.css.

The existing desktop/iPad day header is approximately 66px high. Rebalance the internal gaps and date-circle dimensions to accommodate the numbers, rather than increasing the header height by default.

This matters because increasing it would also affect the sticky Due row's offset and the visible timetable.

Step 3 — Update the phone seven-day selector

Primary location: landing/app.js, renderPhoneWeekStrip(dates).

Add the same Work/Due indicators to .phone-week-day.

Keep the existing 56px phone week strip if legibility permits. At particularly narrow widths, use a compact stacked arrangement for large two-digit counts rather than allowing numbers to overflow into neighboring dates.

Important implementation detail: renderPhoneWeekStrip() currently caches its button markup by week. Codex must ensure counts update after tasks change even when the user stays in the same week. Updating the existing count elements is preferable to unnecessarily recreating all seven buttons and disturbing focus.

Step 4 — Preserve existing Calendar behavior

Do not alter the task list, Due strip, timed deadline markers, event positions, or the full 24-hour time grid.

The new counts must also coexist with the previously planned folding header and elastic timetable scrolling. They should remain stationary with the date tabs while the timetable scrolls underneath.

The Month view is outside this change's scope.

Step 5 — Accessibility

Use accessible names on each complete day button, for example:

Wednesday, November 18. 3 scheduled assignments, 2 deadlines.

Hide the decorative count icons from screen readers, since the full meaning is already available on the button.

Preserve visible keyboard focus, date selection, current-day identification, and adequate touch targets. Counts should not become separate clickable buttons.
